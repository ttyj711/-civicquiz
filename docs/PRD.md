## 1. 产品概述

### 1.1 背景

备考用户需要一个可随时随地刷题、模拟考试、复盘错题的工具；内容运营方需要一套可批量录入题目、组卷、查看学情的管理后台。双方共享同一套题库与考试数据。

### 1.2 产品定位

一站式刷题备考平台，包含：

- **用户端**（小程序 / H5）：题库刷题、模拟考试、错题与收藏、学情统计
- **管理后台**：题库内容管理、考试组卷与发布、用户与考试记录查看、运营看板

### 1.3 产品目标

1. 让用户在 3 步内进入刷题或考试状态。
2. 通过即时反馈、错题本与复盘，形成「练习 → 发现薄弱点 → 针对性重练」闭环。
3. 让运营方以最低成本完成批量录题、组卷与日常运营。

### 1.4 成功指标（建议）

| 指标 | 说明 |
| --- | --- |
| 日均答题量 | 用户端每日提交的题目数 |
| 次日回访率 | 首次答题用户次日再次使用比例 |
| 错题重练率 | 进入错题本并发起重练的用户占比 |
| 考试完成率 | 开考后成功交卷（含到时自动交卷）的比例 |
| 录题效率 | 运营单次批量导入成功率 |

## 5. 业务规则

### 5.1 判分规则

1. 用户答案与正确答案完全一致才算正确（多选题不给半对分）。
2. 答对该题得该题分值；答错或未答得 0 分。
3. 考试总得分 = 各题得分之和；正确率 = 答对题数 ÷ 总题数。

### 5.2 练习规则

1. 开始练习时固定本次题目范围与顺序，中途不变。
2. 单选、判断提交即出结果；多选以「提交本题」为准。
3. 每次作答均记入个人学习历史，用于统计与错题收集。
4. 答错自动进入错题本；同一题累计错误次数。
5. 错题重练只包含「未掌握」的错题。

### 5.3 考试规则

1. 试卷在发布前固定（含随机组卷，也是在成卷时抽取完成）。
2. 同一考试同时只允许存在一份「进行中」答卷；再次进入为续考。
3. 考试过程中不展示答案与解析。
4. 答案可修改，以交卷时的答案为准。
5. 到时系统自动交卷，不允许超时作答。
6. 交卷后统一判分，错题自动进入错题本。
7. 已交卷的答卷不可再次提交。

### 5.4 内容管理规则

1. 题库、分类下有题目时不可删除，需先处理题目。
2. 题目删除采用软删除，保留历史学习记录与统计。
3. 考试已有考生记录时不可删除。
4. 批量导入按行校验；失败行跳过，成功行正常入库。
5. 题库题目数量以实际题目为准（可冗余展示）。

### 5.5 账号与权限规则

1. 用户端与管理后台账号体系隔离。
2. 用户端默认静默登录；禁用用户不可继续使用。
3. 管理员登录后方可使用后台；登录态失效需重新登录。

| 编号 | 需求 |
| --- | --- |
| N-P01 | 首页、题库列表首屏可交互时间目标 ≤ 2 秒（常规网络） |
| N-P02 | 开始练习 / 开始考试响应 ≤ 1 秒 |
| N-P03 | 提交判分反馈 ≤ 1 秒 |
| N-P04 | 后台列表页切换与筛选响应流畅，无明显卡顿 |
| N-P05 | 批量导入 2000 题时有进度反馈，完成后给出结果摘要 |

### 6.2 可靠性

| 编号 | 需求 |
| --- | --- |
| N-R01 | 刷题进度可恢复，刷新 / 弱网中断后不丢已答记录 |
| N-R02 | 考试答案实时暂存，意外退出后可续考 |
| N-R03 | 防重复交卷、防重复提交判分 |
| N-R04 | 导入失败不影响已成功行 |

### 6.3 安全

| 编号 | 需求 |
| --- | --- |
| N-S01 | 管理员密码加密存储，不以明文保存或传输 |
| N-S02 | 接口需按角色鉴权，用户不可访问后台数据 |
| N-S03 | 考试进行中不得提前泄露正确答案 |
| N-S04 | 生产环境必须使用独立密钥与正规微信登录配置 |

### 6.4 兼容与体验

| 编号 | 需求 |
| --- | --- |
| N-C01 | 兼容主流微信小程序与常见移动浏览器（H5） |
| N-C02 | 管理后台适配桌面浏览器 |
| N-C03 | 小程序端提供至少两套可切换主题 |
| N-C04 | 空态、加载态、错误态均有明确文案，避免白屏 |
| N-C05 | 适配刘海屏 / 底部安全区 |
| N-C06 | 倒计时临近结束有明显视觉警示 |

## 7. 内容与文案要求

1. 空态文案尽量鼓励式（如「太棒了，暂时没有错题！」）。
2. 考试须知需明确三条：考试中不显示答案与解析；交卷后统一判分；到时自动交卷。
3. 危险操作确认文案需说明后果（如「已有考生记录将禁止删除」）。
4. 批量导入需在界面说明模板格式、答案写法与上限。

## 8. 范围边界

### 8.1 本期范围（V1.0）

- 用户端：刷题、考试、错题、收藏、学情、主题切换
- 管理端：题库 / 分类 / 题目 / 导入 / 考试组卷发布 / 考试记录 / 用户列表 / 工作台
- 题型：单选、多选、判断

### 8.2 明确不在本期

| 项 | 说明 |
| --- | --- |
| 主观题 | 填空、简答、材料题、人工阅卷 |
| 社交能力 | 排行榜、分享、讨论区、好友 |
| 付费能力 | 会员、订单、支付 |
| 精准学习计划 | 自适应推题、学习路径规划、AI 讲解 |
| 多端管理 | 手机端后台 |
| 多租户 / 多机构 | 机构隔离、多角色权限体系 |
| 消息推送 | 订阅消息、短信、邮件提醒 |

### 8.3 后续迭代建议（按优先级）

1. 分类专项练习入口（能力已预留）
2. 题目笔记持久化
3. 考试编辑与重新组卷
4. 考试开放时间窗口
5. 用户禁用 / 启用
6. 考试记录导出与答卷详情
7. 练习结果「只看错题解析」完善

## 9. 验收要点

### 9.1 用户端

- [ ] 能完成「选题库 → 选模式与题量 → 刷题 → 看结果」全流程
- [ ] 三种题型均可作答并正确判分
- [ ] 答错自动进错题本，可掌握、可移除、可重练
- [ ] 收藏 / 取消收藏即时生效
- [ ] 能完成「选考试 → 开考 → 倒计时 → 交卷 → 看分 → 回顾」全流程
- [ ] 到时自动交卷；考试中看不到答案
- [ ] 断线后可续考、可恢复刷题进度
- [ ] 学情数字与实际答题一致

### 9.2 管理端

- [ ] 能完成题库 / 分类 / 题目的增删改查与启停
- [ ] 有题目 / 有考生记录时相关删除被正确阻止
- [ ] Excel 导入成功行入库、失败行有明细
- [ ] 固定组卷、随机组卷均可成卷；随机题量不足会失败
- [ ] 发布后用户端可见；下架后用户端不可见
- [ ] 工作台统计与错题 Top 列表可正确展示

### 9.3 非功能

- [ ] 首屏、判分、交卷响应达到第 6 节目标
- [ ] 未登录无法访问后台；用户无法越权读取他人数据
- [ ] 空态 / 加载态 / 错误态均无白屏

## 10. 术语表

| 术语 | 含义 |
| --- | --- |
| 题库 | 题目的集合容器，题目与分类均归属某一题库 |
| 分类 | 题库内的知识模块划分，支持二级 |
| 试卷快照 | 考试生成时固定的题目清单与分值，考试中不再变化 |
| 错题本 | 个人答错且未标记掌握的题目集合 |
| 掌握 | 用户主观标记某道错题已学会；再次答错会自动恢复未掌握 |
| 续考 | 接续上次未交卷的考试继续作答 |
| 自动交卷 | 考试时间耗尽时系统强制交卷 |
